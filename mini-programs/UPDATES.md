# 微信与小红书更新手册

## 用户手机怎样收到变化

| 情况 | 操作与可见结果 |
| --- | --- |
| 在线版遇到盘后数据更新 | 既有任务先核验来源、日历、覆盖及三库引用，再切换本机数据。手机通过已配对的私有 HTTPS 接口读取。切回前台或手动刷新会重新核验，行情目标日和最近有效资金日分别显示。此流程无需向平台重复提审程序。 |
| 使用离线版 | 手机读已安装包里的数据，截止日见“数据说明”。收盘任务可在本机生成成对离线包。开发者导入新 ZIP 后即可本机试用。已在手机上使用平台发行版的人，通过该平台实际发布的新包取得新快照。 |
| 改界面、计算展示或新增功能 | 在 `version.json` 维护程序版本。生成对应模式的两份候选包。微信、小红书各自体验、提审、上线。同一应用版本下，每端的包标识可用于核对是哪一次构建。 |
| 用户正在看图时下载好新版 | 支持更新管理器的宿主会给出重启选项，用户可以稍后在“数据说明”中启用。后台到达的就绪事件待回到前台再提示。下载失败时可以继续使用当前包，退出并重新进入后由宿主重试。 |
| 仍在上一轮旧客户端 | 原交付包没有新增的重启提示。平台正式发布后，通过该宿主的重新打开机制取得新版。开发者工具的本地项目需要重新导入或重新编译。 |

平台后台负责实际分发。后台发布、宿主检查到更新、安装包下载完成以及用户重启是不同的时点。[小红书更新机制](https://miniapp.xiaohongshu.com/doc/DC358227) · [微信 UpdateManager](https://developers.weixin.qq.com/miniprogram/dev/api/base/update/UpdateManager.html)

## 盘后和程序发版

以下命令在 `mini-programs` 目录运行。使用项目已有 Python 和 Node。Windows 也可运行项目的 `双端更新.cmd`，参数与 `python scripts/release.py` 相同，直接双击显示当前记录。自动计划仅在北京时间正式交易日23:15增量检查、23:20主补抓，前批未结束时串行接续，内容未变复用已验证候选，不重复制包。人工明确要求更新时可在收盘后执行，不改变夜间计划。页面显示实际数据所属日期，包内目标日继续用于查询范围和版本对账。

```powershell
python scripts/release.py prepare
python scripts/release.py prepare --mode local
python scripts/release.py prepare --mode live --base-url https://你的域名/api/v1 --wechat-appid 你的微信AppID --xhs-appid 你的小红书AppID
python scripts/release.py status
```

- `prepare` 默认生成离线候选。它从已核验的本机价格与快照导出，逐块验证后固定本次使用的版本，在独立目录编译两端、运行回归测试及离线数据对账、重读 ZIP 并校验摘要。两端均成功后才切换对应模式的最新入口。
- 以后按同一模式打包会沿用当前已验证候选的真实 AppID。首次可从已有开发工具工程读取，显式传入的 AppID 优先。打包期间本机数据版本发生切换时，原候选继续有效，下次从新批次重试。
- `after-close` 是既有盘后自动化的收尾命令。它复用正式交易日历，要求北京时间已到 15:30 且本机全市场快照已切到当天。早到、休市或当天数据尚未切换时跳过。晚间补披露使离线内容发生变化时，可生成同日另一份候选。相同数据和程序包复用已校验的归档。
- 版本目录为 `release/versions/<交付ID>/`，内有两份 ZIP、`manifest.json`、宿主编译报告，以及离线模式的数据对账报告。程序版本、程序包标识和数据来源版本可从清单核对。根目录之前按日期命名的 ZIP 属于历史交付。
- `release/latest-snapshot.json`、`latest-local.json`、`latest-live.json` 分别记录三种模式的本机候选。local/live 包仅带程序和连接配置，行情由服务端提供。local 用于同机开发工具，手机联网发行使用具有平台请求域名配置的 HTTPS 服务。
- 本机每轮准备、跳过复用和失败详情写入桌面 `ETF更新日志/北京时间日期`。请求认证头、平台密钥和设备会话均不进入打包过程。

## 分平台体验和上线

将真实 AppID 对应候选的 ZIP 导入各自工具。在开发者后台核对 AppID、版本、包标识/交付 ID 与更新说明，先体验实际配对、真实接口日期及主要页面，再走该平台的审核与发布。界面和线上行情服务应继续兼容仍在使用的 v1 客户端，变更源字段时先以新增字段或新接口发布并验证旧包。

```powershell
python scripts/release.py record wechat <交付ID> trial
python scripts/release.py record wechat <交付ID> in_review
python scripts/release.py record wechat <交付ID> approved
python scripts/release.py record wechat <交付ID> published
python scripts/release.py record xiaohongshu <交付ID> rejected --note "按后台反馈修改说明"
```

这些命令记录操作者已经在平台后台确认的事实。可选备注用于记录非敏感审核信息。两端分别保留当前体验版、审核状态、已确认线上版本和历史。一端驳回时，仅修复该端问题并按实际进度登记；另一端已上线记录保持有效。已有真实项目应先用相应的公开 AppID 重新准备候选，确认包内配置与后台一致。[小红书协同与发布](https://miniapp.xiaohongshu.com/doc/DC980658)

同一天可能生成多次补披露包。上传时把本次交付 ID 和截止日写入平台的版本备注；登记每个审核结果时，使用当初送审的 ID。即使本机已有更新候选，也能准确找回平台正在审核或已经上线的那一包。填写审核要求的测试说明时，使用平台允许的受控测试方式，设备连接码有五分钟有效期。真实账户、服务域名与客户端均就绪后，再安排双端真机体验。[小红书上传与发布流程](https://miniapp.xiaohongshu.com/doc/DC980658)

## 出错时怎么办

| 现象 | 处理 |
| --- | --- |
| 采集迟报或股票价格目标日尚未披露 | 展示真实来源日期和缺口。符合核验条件的旧尾部保留为待更新状态。已核验价格丢失、版本不齐或摘要异常时，本轮候选失败，查看桌面日志后重试。 |
| 导出中断或写到一半 | 导出只在七个数据块都验过后原子切换 `.snapshot-store/latest.json`。使用相同准备命令重试。若指针损坏，可用 `node scripts/export-snapshot.mjs --restore <已核验快照ID>` 恢复后再准备。 |
| 一端编译失败或磁盘写入失败 | 最新交付仍指向上一对完整归档，失败原因记入本轮日志。修复后重新运行 `prepare`。 |
| 本地候选损坏或需要回到上一包 | 用 `python scripts/release.py verify <交付ID>` 核验。通过后可运行 `python scripts/release.py restore <旧交付ID>` 切换本地入口。自动任务会暂停再次选用刚被撤回的同一候选，新的候选仍可被选中。 |
| 平台线上版本有问题 | 各自在官方后台按可用能力处置；需要重新提审历史源代码时使用已核验的归档。确认平台实际上线的目标版本后，用 `record <平台> <旧交付ID> rolled_back` 登记。切换本地入口只改变本机交付选择。 |
| 手机上版本或日期看起来不对 | 在“数据说明”核对数据源、程序版本、包标识和目标日。对照 `status` 中该平台的已确认线上版本，再检查设备网络、配对会话及宿主是否已就绪。 |

真机 A→B 下载、稍后重启、审核驳回与官方回退需在真实账号和设备上验证。没有平台确认记录时，本地台账显示尚无记录。
