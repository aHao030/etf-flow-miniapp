# M3 前端页面与交互草案（miniapp-frontend）

- 版本：v0.1 草案
- 日期：2026-10-30
- 范围依据：计划书 §5.3（5 个 MVP 页面）、§7（合规要点）、§8.1（默认方案：盘后 T+1、行业/主题 ETF + 主流宽基、体验版内测）
- 前置依赖：M2 后端 API 契约（见文末问题清单）

---

## 1. 页面结构与导航

采用 3 个 TabBar + 2 个二级页面，共 5 个 MVP 页面：

| 页面 | 路由 | 级别 | 职责 |
|---|---|---|---|
| 首页·榜单 | pages/index | Tab | 流入榜：周期切换 + 行业筛选 |
| 个股详情 | pages/stock-detail | 二级 | 流量序列图、ETF 来源拆解、流入强度 |
| ETF 页 | pages/etf-detail | 二级 | 单只 ETF 份额/规模走势、对成分股影响 |
| 自选/提醒 | pages/watchlist | Tab | 自选列表、订阅消息提醒 |
| 我的 | pages/profile | Tab | 口径说明、免责声明、关于 |

导航闭环：榜单 → 个股详情 →（来源拆解）→ ETF 详情 → 返回。自选个股/ETF 从各页均可添加入口。

## 2. 各页面要点

**首页·榜单**
- 顶部周期 Tab：单日 / 5日 / 20日（切换只换请求参数，页面结构不变）。
- 筛选：全市场 / 行业（行业字典由后端接口下发，避免前端硬编码）。
- 列表项：排名、名称代码、**估算净流入**（红涨绿跌，金额单位随量级自适应 万/亿）、流入强度徽标、环比变化箭头。
- 页顶常驻口径披露条（见 §4）；下拉刷新；触底分页；骨架屏占位。

**个股详情**
- 头部卡片：名称/代码、流通市值、流入强度、5/20 日累计，右上自选星标。
- 流量序列图：近 60 交易日，柱状（单日）+ 折线（5/20 日均值）双系列，随周期 Tab 联动。
- ETF 来源拆解：TOP 10 ETF 列表（贡献金额 + 占比横条），点击跳 ETF 详情。
- 图与拆解区均就近标注"估算值"。

**ETF 页**
- 头部：ETF 名称/代码、最新份额、估算规模。
- 图表 1：份额变化序列（日频柱状）；图表 2：规模走势（份额 × 单位净值，折线）。
- 列表：该 ETF 对成分股影响 TOP N（个股 + 估算流入），点击跳个股详情。

**自选/提醒**
- 两个分组：自选个股 / 自选 ETF，按当日估算净流入排序；左滑删除。
- 提醒：开关触发 `wx.requestSubscribeMessage` 一次性订阅授权，未授权/被拒状态明确提示并给重新引导。
- 空态：无自选时展示榜单入口引导。

**我的**
- 数据口径说明（完整版）、免责声明、数据来源列表、隐私政策、关于/版本号、清除缓存。

## 3. 图表选型：echarts-for-weixin

- 序列图统一用 **echarts-for-weixin（ec-canvas 组件）**：柱状图（份额变化/单日流）、折线图（规模/累计趋势）。
- 按需裁剪 echarts.min.js（仅 bar/line/grid/tooltip），放入 **echarts 分包**，首屏榜单不加载图表，控制主包体积。
- 图表数据经 `setOption` 传入 canvas 绘制，**不进 setData**；序列点控制在 ~120 以内。
- 小程序 canvas 限制：tooltip 用 touch 事件自行实现轻提示，禁用浏览器式悬浮；多图页面延迟渲染（onReady 后再 init）。
- 简单占比横条用纯 CSS/进度条实现，不引入图表库。

## 4. 口径披露呈现位置（§7 合规硬要求）

> 统一文案：**"估算值：基于 ETF 份额变化与持仓权重推算，非真实买卖资金数据。"**

| 位置 | 形式 |
|---|---|
| 首页榜单表头下方 | 常驻一行小字 + ⓘ 图标（点击展开简述） |
| 个股详情图表下方、来源拆解区 | 常驻小字标注 |
| ETF 页图表下方 | 常驻小字标注 |
| 订阅消息推送文案 | 文案内嵌"（估算）"字样 |
| 我的页 | 完整《数据口径说明》+《免责声明》+ 数据来源列表（交易所份额披露、基金定期报告等） |
| 全站字段命名 | 所有金额字段统一命名为"**估算净流入**"，禁止裸称"净流入" |

补充规则：所有页面不得出现收益承诺、荐股表述；免责声明注明"不构成投资建议"；个股详情不展示行情价格/涨跌幅（降低类目合规风险，待 Lead 确认，见问题 9）。

## 5. 关键交互流程

1. **榜单→详情→ETF 闭环**：筛选/切周期 → 点击个股 → 看序列图与来源 → 点 ETF → 看份额影响 → 返回。
2. **自选管理**：星标/取消 → 本地 Storage 即时生效 + 云开发 openid 同步（需登录态，见问题 4）。
3. **订阅提醒**：开关 → 授权弹窗 → 记录授权结果上报后端 → 后端定时任务发送（前端只负责授权与开关状态）。
4. **异常与空态**：接口失败显示重试按钮；当日数据未更新时显示最新 `trade_date`；加载中一律骨架屏。

## 6. 性能要点

- 盘后数据 T+1、一天不变：**请求结果落 Storage 缓存 + trade_date 校验**，仅下拉刷新才强制重拉。
- 主包只含 3 个 Tab 页 + 公共组件；echarts 与两个详情页按需分包加载。
- 榜单分页 20 条/页，列表项不渲染图表；图标用 CSS 绘制，避免图片资源。

## 7. 为 M3 预留的问题清单（需 Lead / 后端确认）

1. **API 契约**：接口路径、字段命名与单位（flow_1d/5d/20d、intensity、share 等）、分页参数、错误码——M2 出 API 文档后对齐。
2. **序列数据格式**：图表接口返回全量 60 日还是按需分段？金额单位（元/万/亿）？
3. **行业字典**：行业分类标准（申万/东财）与筛选值由后端下发？
4. **登录体系**：自选/提醒是否用云开发 openid？个人主体体验版下订阅消息可用性？
5. **订阅消息**：模板 ID 由谁申请？推送触发在后端（云函数定时）还是前端？
6. **ETF 覆盖列表**：行业/主题 + 主流宽基清单是否提供字典接口？
7. **UI 规范**：是否需要统一设计稿/色彩规范（红涨绿跌、字号、主题色）？
8. **trade_date**：接口是否返回数据日期，页面如何提示"数据截至 T 日"？
9. **行情字段展示**：个股/ETF 是否展示价格与涨跌幅（涉行情类目合规风险，建议 MVP 不展示，需确认）。
10. **体验版内测**：M4 真机测试机型范围与体验版成员名单由谁确定？
